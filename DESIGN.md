# Post Rider: Design

Two Minecraft versions are supported: the latest (now 26.3, NeoForge 26.3.x, Java 25) on `main`, and 1.21.1 (NeoForge 21.1.x, Java 21) on the `mc/1.21.1` branch. Both get the same features and the same mod version number (the jar name says which Minecraft it's for). New work lands on `main` first and is cherry-picked to `mc/1.21.1`; when Mojang releases a new version, `main` moves up to it and there is no branch per 26.x release. Standalone (no other mods required); players are recommended the Concurrent Chunk Management Engine (C2ME) where there's a build for their version, but nothing depends on it, and development runs are the mod alone unless `-Pc2me`/`-Pdh` is given. All items are server-side vanilla-style items.

## Mod loaders
- Post Rider ships on NeoForge, Fabric and Forge, for every Minecraft version it supports, and behaves exactly the same on all three. NeoForge is the reference: the mod starts there, and the other two are checked against it.
- One project with a module per loader: `common/` is the whole mod in plain Minecraft code (with the unit tests and game tests), and `neoforge/`, `fabric/` and `forge/` only connect their loader's events and registries to it. `parity/hooks.md` lists every such connection.
- Fabric uses Forge Config API Port for the server config, so the file, keys and comments are the same as on NeoForge; Fabric players install it and Fabric API.
- The Dailies compat is NeoForge only, as Dailies is a NeoForge mod.
- On Fabric and Forge (Forge 66 has no ticket API of its own) the riders' chunk tickets are kept as NeoForge keeps them (per rider, held loaded with or without natural spawning, saved with the world and sorted out when it loads), and keeping the dimension awake with no player in it, as NeoForge's tickets do. The config's per-world override folder is `serverconfig/` on Fabric (Forge Config API Port) and `syncedconfig/` on NeoForge. On Forge the config is a COMMON config: the same `config/postrider-server.toml`, keys and defaults, but not synced to clients (they never read it), with no per-world override, and read when the game starts.
- Parity is checked by registry manifest, the unit tests and the game tests on each loader, and seeded trips (the game tests' trials, the frozen ocean seed postrider12, and the land seeds postrider, postrider2 and postrider3), with `loader-parity-check`. A loader build is only released after it passes.
- A world isn't moved from one loader to another (it doesn't happen in practice), so each loader may keep its own saved data where it likes (the riders' chunk tickets, the per-world config override folder).
- Releases go to CurseForge only (one project, a file per loader); not to Modrinth until its AI policy changes.

## Workflow rules
- Every model is built in Blockbench first (never hand-written JSON imported later) and approved before work continues.
- Every feature ships with unit tests (`common/src/test/java`, run on every loader).
- Movement is also checked in a real world by GameTests (`gametest` package, run with `./gradlew runGameTestServer` after any change to how riders get about): each builds a small scene (a shallow river, an island, the bay, a stream with a bridge, a ditch, a narrow channel) and watches a rider deliver across it without wading, being teleported free, rowing where he should ride, or leaping a ditch twice.
- Anything uncertain gets asked, not assumed.

## Mailbox
- Style: US post box on a wooden post, door at the front, side flag that goes up when the inbox has mail. Two blocks tall. Only the box takes the dye colour.
- The flag is red on every colour except the red mailbox, which gets a yellow flag so it stands out.
- All 16 dye colours. Recipe: iron ingots around a chest, with a fence underneath (comes out white). Craft with a dye to recolour, or right-click a placed mailbox with a dye.
- Placement is always allowed. If it has no sky view, the placer gets a warning that the postman will probably lose mail.
- Owner types a name in the mailbox screen. Names are 3–24 characters and unique server-wide, ignoring case. A player can own several mailboxes.
- Only the owner can open it, and only the owner (or an operator) can break it. No explosion takes it down, whatever its size, nor drops a copy of it.
- Inbox: 27 sealed parcels/letters. When broken, the contents spill on the ground and the name is freed.
- Sending: the mailbox screen has a 9-slot parcel area, an address picked from a list of all mailboxes, and a Send button. Postage is free.

## Parcel and letters
- Parcel item: sealed, holds up to 9 stacks, and its tooltip doesn't show what's inside. Right-click to tear it open: like emptying a bundle, everything inside is thrown on the ground in front of you, and the parcel is used up.
- Letters: craft a blank Letter, use it to open its own writing screen, and finish it to get a Written Letter. Using a Written Letter opens it to read. It stays a readable item you can keep.
- Put a Written Letter in the parcel slots to send it. If the parcel holds nothing but one letter, it travels and arrives as just the letter. If there's anything else in it, everything (letter included) arrives inside a Parcel.
- Every screen shares the old-time post office look: walnut panelling, a parchment work surface, brass fittings, postage-stamp tabs, red wax for the main action, and ledger pages for lists (`client/gui/PostOfficeStyle`, `textures/gui/post_office.png`).
- Failure letter: a readable Letter item (book-style page) giving the reason (e.g. "killed by a Zombie"), the Lost Parcel's X/Y/Z and the addressee.

## Postman
- The crew: twenty riders, each always the same person with their own face, name and horse (`Roster`), so you get to know them ("yay, Chris is here"). Only one of each is out at a time, which is also the 20-rider limit. Chris (just "Chris") rides Lightning, the fastest horse at 10.5 blocks/s; Gus Tanner's Molasses is the slowest at 7.0. Eight are women: Mattie, Rosa, Clara, Hattie, Lottie, Nell, Ada and Sadie. They ride on a slim build (7-wide head, 3-wide arms) with female-coded faces, and messages about them say "her".
- Each rider has a signature bandana and small outfit touches (vest and shirt colours, rolled sleeves, a patched vest, inky cuffs). Long hair (a braid, buns, pigtails, hair down the back) is drawn with extra head parts shown only for whoever wears it. Skins are generated by tools/rider_skins.js in Blockbench from the base skin.
- A custom player-like mob with an Old West post rider skin (wide-brimmed hat, bandana, leather vest), riding a vanilla-style horse. His hat sways a touch from side to side with his step and bobs with the gallop (keyframed on the hat bone in the walk and ride animations).
- His horse wears a mochila: a leather cover over the saddle with four boxy mail pockets (two on each side). Each horse gets a random vanilla coat and markings, and a random speed that is never below 7 blocks/s.
- Pickup: he appears in a puff of smoke at the sender's mailbox, takes the parcel and summons his horse.
- Riders only collect in daytime: mail posted after dusk (6pm game time) waits in the queue until 6am, and the sender is told so.
- He appears and vanishes in a puff of smoke, and his horse arrives (when he whistles) and leaves the same way. If his horse is killed, that's it for the trip: no whistle brings it back, the way on is planned on foot, and he crosses water without it; on his next delivery he has it again. The horse only appears where there's room for it and for him on its back (three clear blocks up), never under a low roof; and if he's ever carried under one on horseback, he gets down rather than suffocate and plans on from there on foot. Every hurt he takes is noted in the log (what, where, how he stood).
- Every rider and every horse gets a random Old West name.
- Delivery: within 6 blocks of the mailbox, and within 3 blocks of its height (a box on a tower is reached by its ramp, not from its foot), he dismounts, walks up, puts the parcel in the inbox and vanishes in smoke with his horse (never while a ladder or a bubble column still has him: he's seen to the end of it first). A ladder or a bubble column is entered square (he's set into its block when he's up against it from the side, as a ladder's thin side can't be climbed).
- Same dimension only, no distance cap. He keeps a 7×7 area of chunks loaded around himself so he can plan a 48-block stretch ahead; only the 3×3 he's in the middle of ticks (the outer ring grows and spawns nothing). At most 20 riders out at once; extra mail waits its turn.
- The ice hopper (blockbench/ice_hopper.bbmodel): a boat for players, sized like a vanilla boat with two seats, spruce planks with an upturned bow continuing the hull bottom at 25°, shod with iron underneath and along its leading edge, and oars that swing as it's rowed. Under way in the water, or sliding on ice, with ice ahead at its own level or one block up (ice of any kind, with two clear blocks over it; the bow's middle and both corners look ahead, so an angled approach hops too), it hops up onto the ice and slides on without stopping, as fast as any boat on ice; bumped against the ice it has no way on at all, so it hops the way it's facing whenever it's being rowed forward, and comes up onto the ice with a push. It slips off the ice's edge back into the water the same way. Its item is the boat itself in miniature (a 3D model built from the Blockbench model at half size, skinned with the boat's texture, which is added to the block atlas for it since item models draw only from there), shown in the hotbar, the inventory and the hand. Afloat its hull is drawn up at the waterline as a vanilla boat's is; on ice it sits where it is. A lone rower takes the front seat and a passenger the back one, sat into the seats rather than through the hull. Crafted from any boat and two packed ice; it comes back as its own item when broken, and is a vanilla boat otherwise.
- To the barge, sea ice is water: ice of any kind whose top is no more than two blocks above the block of the surface it's on (level with it, or a block of ice standing on the sheet) counts as a surface, so it slides from open water onto ice and off again without stopping (with ice ahead the hull rises to the ice's top before it gets there, a quarter block a tick at most, looked for at the bow's middle and both corners so a sheet met at an angle is climbed too; afloat it sits a pixel lower than the ice), a shade faster on the ice (1.5x, no oar strokes), the hull resting on top of the ice rather than sunk in it; ice higher than that (an iceberg, a frozen bank) is a bank like any other. It looks for its level a touch under the hull, so afloat and on ice alike that's the surface's block, and ice a block up is never climbed.
- Ice fields (the frozen ocean, the deep frozen ocean and frozen rivers, by biome; and ice underfoot in a loaded chunk) are barge country: a cell with most of its sampled columns in one is water to the map, crossed by barge like open water, never ridden; he launches at the ice's edge as at a bank and lands where real ground meets the ice: ice at the barge's level is no landing place while the barge can slide on (only when he's stuck afloat and any shore will do), but ice standing more than a block above the barge's own level is a bank like any other: the barge can't slide up it, he steps ashore onto it, and hard against it with nowhere to step off its cells are struck off the map like a bank's though they're water to the map. A cell that's only partly ice costs a horse four times normal, and the stretches through the blocks keep off ice too (a step on ice costs three), so a way round ice doesn't cut its corners. A chunk read off disk doesn't give its biomes; its ice is known once it's loaded and read afresh.
- Prefers land: he never wades or swims (the one water he goes into is a bubble column, on foot: see Route). He takes the barge only when riding round would be more than twice as long as the route with the barge (see Route). Otherwise he crosses water on a ferry barge (flat barge with railings and a lantern post) that carries him and the horse (if he's on foot at the water's edge, the horse appears aboard beside him: it always crosses with him). It's about 3 blocks wide by 5 long, and rides high: only the bottom pixel of its hull is in the water, so it floats in water a single block deep. Its hit box is a touch narrower than the hull (2¾ blocks) by 2¾, from the bottom of the hull up to the tops of the railings, so it bumps into a bank at the waterline rather than sliding up onto it, and in a lead just wide enough for the hull it has a little to spare (a box the full width caught an edge at every bend). he sits on a bench at the bow rowing with a pair of oars (the row animation), facing forward like a boat, and the horse stands on the deck behind him. The barge appears in a puff of smoke at the water's edge and vanishes in smoke on the far shore. A rider sets out from the stand in front of the sender's box, or, with that stand blocked (a bush, a bank, a tree), from the nearest standing room. He steps ashore on the dry ground nearest the bow that leads towards the box, preferring ground with room to put the horse down; never onto a scrap of shore with no way on (a sandbar, an islet: looked at from the barge, hardly any of it to get about on and the way on not found), which is noted as leading nowhere while he rows on; ground with room for the horse up to six blocks further from the bow is taken before a strip of beach with none; with no room for it at all where he lands the horse goes in a puff rather than be wedged in the rock, and he whistles for it at the first place along the way with room. Hard against a shore for a few seconds with nowhere to step off (a cliff, a wall), the barge notes that shore as leading nowhere and the way across the water is worked out again round it. If no way across the water towards where the water leg goes can be found three times running (a strip of land the cells can't see closes it off), the water ahead is struck off the map like a stretch of land that fails and the route redone round it, rather than rowing at the bank over and over; the barge's own way across still rows through water in struck-off cells (it keeps clear only of the water in a shore that led nowhere), or each strike would box it in a little more. Cells struck off never include the goal's or those next to where he starts from, so a route can always begin and end. Landed on a scrap of shore with no way on (a ledge under a cliff, an islet), he puts out again in the barge whichever way the water lies and tries the next bit of coast; that shore is noted as leading nowhere, and neither the barge's way nor a later landing goes near it. Its lantern's flame is drawn full-bright so it glows at night (it doesn't light the surroundings).
- The barge: when his planned route reaches a water leg, he launches the barge on open water at the shore (the barge stops with its bow a block short of anything that isn't open water, as its hull is longer than its collision box and his seat is in the bow: pushed into a bank or a wall he'd be crushed; and if he ever is, it backs off a block; open water has three clear blocks over it, for the barge, the horse on its deck and himself: he never rows under a bridge, an overhanging tree or a cave roof, which would crush them against it; needs room for its 3x5 hull) with his horse aboard. Once afloat he works the route out again from the water: he rows as little as he can, to the nearest land that takes him on to the mailbox, never back onto the shore he put out from. It rows at a boat's speed (8 blocks/s), keeps going day or night, and follows its own block-by-block way across the water (A* through the loaded chunks, a block of open water either side of the hull and dearer where there isn't a second, so it keeps to roomy water where it can; dearer too near drowned and ocean monuments), steering for a point 5 blocks along it so it rounds the bends of a river, and slowing down in tight turns (down to 30% for a right angle); caught on an edge with the way going on, it steers back onto the line of the way before going on rather than push at what it's caught on; in tight water (anything but open water within two blocks) it steers for a point only 2.5 blocks along rather than 5, so the hull follows the bends of a lead between bergs rather than cut them; and with its side caught on a corner (bumping, with open water ahead of the bow) it backs off a block every second until it's clear. It cuts through kelp, seagrass and lily pads in its way (they're removed, nothing dropped), and counts water with plants in it as open water. At the end of its way across the water it runs the bow up onto the bank, and he steps ashore wherever the bow is against land at the end of that way (or near where the plan lands, or after running hard aground); if the barge ever stalls beside land he steps ashore there rather than being teleported. On foot with the water within 15 blocks, he walks down to it rather than calling his horse, and whistles for it once he's across (unless the mailbox is within 15 blocks of where he lands: then he walks the rest). It lands by the bow at the far end of the leg: the horse appears on the bank, he remounts, and the barge vanishes. He's ashore at least a second before putting out again (across an islet he'd otherwise be back in the barge in the tick he landed). The barge can't be harmed.
- On the water he steers well clear of ocean monuments (24 blocks) and of any drowned he can see (12 blocks). Drowned (tridents included) and guardians still hunt him like a player, and pufferfish sting him, so a crossing can still go wrong.
- Takes any damage a player would: mobs, lightning, fall, fire, drowning, and players. Every hostile mob that hunts players targets him (spiders only in the dark, as with players), and creepers explode on him.
- He carries two potions of Instant Health II a day (restocked at 6am). Whenever he drops below half health he drinks one on the spot (1.6 s, even mid-gallop), healing 4 hearts. They're for him only, not the horse, and any left when he dies break with him.
- If the horse dies, he carries on on foot (still using the barge on water).
- At dusk he looks up to 8 blocks around for a flat pitch big enough for the tent (pegs included) and a seat in front, with at least two clear blocks before any drop, and walks to it. With nowhere suitable he plays and sleeps in the open. Whichever, he wakes at 6am with full hearts.
- Mannerisms on the road give him life. They only move his head, arms and hat, so they play on horseback or on foot:
  - Greetings: a player who comes within 12 blocks in sight gets a wave or a tip of the hat, once per encounter (it resets after 32+ blocks apart). Villagers within 8 blocks get a hat tip now and then (30%).
  - Every 20-45 seconds he does something that suits where he is: wipe his brow and swig from his canteen in hot biomes by day, shiver in the cold, pull his hat down when rain starts, yawn and stretch in the evening, scratch his head on a detour (and after being teleported free when stuck), shade his eyes or check his pocket watch on a long ride, swat flies in swamps and jungles, pat his horse and look back over his shoulder while riding, and anywhere check his satchel, adjust his hat, hum along, roll his neck, crack his knuckles or, now and then, eat a hunk of bread (two bites, with the munching sound and crumbs). Never the same one twice running.
  - Once within 100 blocks of the destination he reads the letter's address.
  - Only while travelling: never while fleeing, camping, at a mailbox, or drinking.
- Being stuck is measured by two clocks, how long since he last got nearer (30 s) and how long since he last moved (5 s); time spent with the route being redone or waiting for his horse is excused from both, but doesn't start them again (a route redone every few seconds, each time the same, is being stuck); a route redone on purpose after the way ahead is struck off doesn't count as one more redo without progress. Cells struck off are forgiven when no route is left (more likely the strikes walled him in than the world), but at most twice in two minutes: forgiven over and over in one place he'd strike and replan the same route for ever, so after that the strikes stand and the usual way out (a way found through the blocks, or a jump free) gets its turn. In the barge the not-moved clock is 15 s, as a barge pressed against a bank takes a while to back off and turn.
- Nothing can shove him while he's planted on a job (camping, in the tent, or at a mailbox picking up, whistling or delivering); on the move he's jostled like anyone else.
- Campfire (blockbench/campfire.bbmodel, a lit and an embers model; the light_fire animation and the striker and flint props are in the postman models): after the tent goes up he kneels and lights a campfire with a flint and steel (three strikes with the striking sound; the third catches), on the block in front of his seat if it's empty with solid ground under it that isn't ice. A camp on ice (the seat or the fire's spot on ice of any kind) is a cold one: no fire is lit, there's no flint and steel and no harmonica, and he sits shivering every five seconds until bedtime. It's a real block, since only blocks give off light, but temporary: placed only where nothing is, removed when he packs up at 6am or his camp is abandoned, and it removes itself if it's ever left without a camp. Its light starts at 15 and steps down steadily until 3am, when it burns down to embers at light 3 until morning; the bright early evening keeps monsters from spawning close to the camp. It's harmless (no burning, no spreading fire, no cooking) and can't be broken or put out by players. Smoke and crackling while lit, a faint glow from the embers.
- He keeps his eyes on his work: he never turns to watch players, and his head only follows where he's looking while he isn't busy with an animation.
- If anything attacks him while he's camping, he abandons camp (the tent packs away) and flees on foot from it and any hostile mob nearby until daylight, then whistles up his horse and rides on.
- Camps every night (dusk to dawn) in a tent entity model, with no blocks placed. At dusk he hammers in the pegs (holding a hammer, with a knock on each blow), the tent goes up behind him in a puff of smoke, and he sits playing the harmonica (CREDITS.md; each player's game plays it from him, so it follows him, and fades out over a couple of seconds when he stops) until monsters come out (about 7:11pm), then turns in, lying on his back with his hat over his face and his boots sticking out of the door. While in the tent, mobs only notice him within 4 blocks. At 6am the tent packs away in a puff of smoke; he gets his map out and works the route out afresh from there, then whistles for his horse if there's room for it (and for him on its back), else sets off on foot and gets back on at the first place along the way with room. If night falls on water, he keeps going until he reaches land. If the night is skipped, he packs up in the morning.
- Following the way, a step he's come level with is skipped only if the one after it is within a block of his level: skipped on a climb, the horse bounced at a two-block face and fell off the side of a gravel slope; skipped on a descent, two drops would be one fall. Never a drop of two or more blocks straight after a drop of any size, on foot or on horseback: landing on a ledge a block wide he's over its edge before he's down and falls the two together (seven blocks down a bank of three-block steps cost him two hearts, and three down, one down and three down again fell the lot), so there must be a level step between. On foot he steps up a stair or a slab rather than hop it (vanilla has a mob hop whenever its feet are below the top of the block it's in, and a hop at a turn of a stair one block wide carried him over the edge). He never gets down from the horse while it's in the air (landing a leap, say): got off over a gap he'd fall into it, so he waits for it to land. His horse gallops at full speed (but is held to a walk wherever the next few steps of the way go down, so it steps down a block at a time rather than gallop off a ledge and skip a step; on foot he walks there too, rather than run); likewise within two blocks of anything he'd never step on (fire, a campfire, magma, cactus, berry bushes...), where the horse also has to come right up to each step of the way rather than turn for the next one early, so it never cuts a corner round a hazard (since 26.1 a horse is hurt by anything it brushes in passing, and it stands only about 0.3 of a block inside its blocks), and leaps gaps of up to 3 blocks onto ground at about the same height: only where his plan crosses a gap, from the take-off straight at the landing (never at a hole beside the way), only with five blocks of headroom all the way across (a leaping horse rises a couple of blocks with him on it: under a low canopy he'd be smothered in the leaves), and once over he rides on rather than turning back to the planned landing spot. He never aims for, jumps onto or teleports onto lava, fire, magma, cactus, berry bushes, powder snow, dripstone, cobwebs or water.
- Route: his own two-level A* (hierarchical, re-planning as he goes), in place of vanilla pathfinding.
  - Long-range plan: A* over a grid of 8x8-block cells covering the whole trip, from each cell's ground height and whether it's water (four columns sampled per cell). Terrain comes from loaded chunks first (read from the blocks at the sampled columns: a tree, a giant mushroom or bamboo is looked under to the ground it stands on, where the game's heightmaps would count a trunk as a cliff), then chunks saved on disk, and where neither has it from the world generator's noise (its base heights, as the game places structures by), so no chunk is generated for a plan. Where the ground comes from the noise, one column in the middle of each cell stands for the cell's four (a quarter of the work: each column is a fraction of a millisecond of noise), and the noise is sampled a column at a time in the tick's spare time (whatever the server leaves of its tick, a quarter of it kept free, between 4 and 30 ms for all riders together), so a long trip into land nobody has explored is surveyed in some seconds rather than in one tick that stalls the server, and his route is worked out before he sets off rather than half guessed; ground off disk or from loaded chunks is read at once, four columns a cell. A trip further than a thousand blocks is planned a stage at a time, each to the nearest land to a point a thousand blocks along the straight line, the next stage planned from there. Before he sets off on a stage, with the map still out, the chunks along the whole of it (three chunks wide) are held, and so loaded or generated, and read into the survey as the real ground; the plan is checked against them and redone if a land leg has turned out to cross water or ground too steep to ride (a cliff face of more than eight blocks inside a cell, or a step of more than twelve from one cell to the next: the same rules the plan was made by, so a plan that fits the real ground passes), or a water leg dry land, and the log says what didn't fit and where (a stage's goal point that turns out to be water is no misfit: he'd arrive there by barge and plan the next stage afloat, and redoing the route couldn't move it); a couple of times at most, and then he goes. On the ride a window of chunks four hundred blocks ahead along the plan is kept the same way, under his own name, and the check is made again every half minute (the chunks held ahead aren't saved with the plan: when the world loads, a working rider keeps only the ticking 3x3 round him, and the rest is held again once he's going, so nothing is held for ever after a restart); a river or a lake the noise doesn't show is met by the local plan, which can't get through it, and the long-range plan is redone round it. Every loaded chunk of a tile is read afresh every few seconds, so a bridge or a canal just built is seen at once; a tile read partly or wholly off disk or generated is kept for ten minutes, its loaded chunks still read afresh and its other chunks read from the ground as they load. Steep climbs cost more; more than twelve blocks up or down from one cell to the next is a cliff (or a chasm's wall) and isn't crossed at all, and nor is a cell with a cliff face of more than eight blocks inside it (its highest sampled column over its lowest), unless it's the mailbox's own, and the barge isn't landed on one either (a shore that leads nowhere); a move corner to corner never squeezes past such a cliff on either cell beside it, as he'd pass over it (less is left to the local plan, which sees the bridge or the ramp the cells can't); the void can't be crossed. Water cells are only crossed as barge legs, with a cost to launch and land. A cell is water if three or more of its four sampled columns are; so a strip of land across a river narrower than about 16 blocks can be lost between two cells and the plan rows across instead of riding round to it (a narrow channel the other way round is caught by the local plan, which can't get through it, and the plan is redone). While the route is still being worked out (the sea ahead being surveyed a chunk at a time), a barge rows straight for the box, round what's in the way, rather than making for the end of the plan so far (which may be mid-ocean); the plan catches up with him. While choosing the way with the barge, rowing is priced at 4x riding, so the water legs are as short as they can be (straight across a river, to the nearest land that leads on); whether the barge is worth it is judged at its real cost (1.1x riding). He plans twice: with the barge allowed, then over land only (stopping as soon as the land route can't come within twice the barge route's cost). He takes the land route unless it's more than twice as long, or there isn't one. A Nether-style world with a roof gets no long-range plan, just a straight line.
  - Local plan: A* over blocks inside the chunks he keeps loaded, to a point about one stretch (48 blocks) ahead along the long-range plan, or to the mailbox. A stretch that doesn't reach its goal (the best the search could do in its budget) is taken only as far as its first drop of more than a block: a basin got down into on a guess has no way back up it and no way out but a jump; once nearer, the next search either reaches the goal through it or goes another way, and if nothing of the stretch is safe to take it counts as no way through. The last stretch, to the mailbox itself, is searched backwards first, from the mailbox towards him with every move turned round (a drop reversed is a climb from above, a mount reversed a dismount): a mailbox in a room is found by the room's few ways out, where a search from him would spend its budget on the open ground outside the room's walls, which looks nearly as close. If that doesn't reach him, the search from him runs as usual. Water and hazards can't be entered. Moves: walk (8 directions, no cutting corners), step up 1, drop down (3 at most, in the saddle or on foot: any further hurts, and a horse's fall hurts its rider too), leap gaps of up to 3 blocks on horseback, and climb ladders, vines and scaffolding on foot. On horseback he needs a 2x2 footprint 3 blocks high with ground under all four corners (never half over an edge); on foot, 1x1 and 2 high, or 3 high standing in a floor that lifts him more than a fifth of a block (a bed, a bottom slab, deep snow: 1.8 tall on a straw bed under a tent's roof, his head is in the roof; a carpet or a thin layer of snow leaves him inside the 2). He uses existing caves and tunnels when they're the better way (a little dearer than the open air), and never digs or breaks blocks.
  - Ladders and vines: a column of them is climbed with the path put aside (jumping to climb, sliding to descend); where the way goes on up onto a ledge above the last rung he climbs to the top of that block first, as at the top of a ladder (stepping off level with the rung he'd step into the air beside the ledge and fall); at the foot of a vine that hangs to the water he swims up into it. On the lip of a drop of two or more that the way goes straight down, on foot, he's nudged off it the way the step goes: the path follower never counts a step that far under its feet as reached, and would stand there.
  - Doors, on foot only (no horse goes through a doorway): any door, wooden or iron (no button or lever needed), is part of the way at a small extra cost (a moment at the handle). Coming up to one he opens it, and once he's through and clear of it he puts it back as he found it: shut again if it was shut, left open if it was open. Any still open when he leaves the road (delivered, camping, lost) go back then.
  - Bubble columns, on foot only: he goes up a column rising from soul sand (into it at any height, out onto a ledge beside its top, where the water throws him up: level with the top water block, or a block higher) and down a whirlpool over magma (into it from a ledge level with or a block above its top, and straight off the magma at its foot onto the ledge beside it, never up). The horse can't be in one, so he gets down first and whistles it back after. These columns are the one water he enters; they don't count as wading.
  - Climbing on foot: where only someone on foot can go (a ladder, a gap too narrow or low for the horse), the plan dismisses the horse (a puff of smoke), carries on on foot, and whistles it back at the first spot with room for it (one where the horse stands squarely). Going on foot costs twice what riding does, and whistling the horse back costs about ten blocks' riding, so he only walks when riding round costs much more, and gets back on as soon as there's more than a few blocks left to go. A ladder or a bubble column is not left to the path follower (pushed sideways on a ladder a mob climbs up, whichever way the path goes): from the first column step he's held square in the column with no path, the ladder (he jumps to climb, slides to descend) or the water takes him, and the path is handed back at the other end. While he's in one he climbs hand over hand (the climb animation, on a ladder) or drifts, arms a little out, bobbing gently (the drift animation, in a bubble column). At the top of a rising column the water would hold him bobbing in the air, and the magma at the foot of a whirlpool burns, so from the top of the one and from just above the foot of the other he's pushed across onto the ledge beside it. The way he's given is never worked out again by vanilla's own pathfinder when a block near it changes (a door he's opening, say), as vanilla would do.
  - Re-planning: the local plan is renewed as he nears its end, when blocks on it change, or when he's pushed off it. If the local plan can't get past part of the long-range plan, those cells are marked blocked for this trip and the long-range plan is redone. Heading for a water leg, he makes for the bank (the last dry ground on the way to it), from where the barge can always be launched; if he can't get nearer the water he launches from where he is. A route planned afloat always begins over the water (his cell is water for him whatever its columns say: an inlet in sea ice reads as ice), and the shore struck off round the barge is kept off it; with no route left even so, the struck shores are forgiven and he lands where he can. A shore is written off as a scrap (not stepped onto) only if, searched from the landing towards the mailbox itself, there's hardly any ground to get about on: a ledge, an islet, not the ice sheet round an inlet. Stuck in the barge, he steps onto a shore within 12 blocks; with no route left at all, onto one struck off as leading nowhere too. Stuck on land with water at hand, once the map has been redone round the way ahead and the search from him has run out of ground without finding the way (an ice floe, an island, not just a scrap), he takes to the water in the barge. His horse is put down on any footing two blocks by two that takes in his block when the usual spots beside him have no room (a strip of ice two wide). Water up to eight blocks below him counts for a launch from land (he gets down into the barge, and a drop into water hurts nobody), so a bank well above a river is put out from rather than searched along for a way down. If any stretch can't be planned and there's open water that way he could launch the barge on, he takes the barge whatever the long-range plan said (a river or channel narrower than its cells can pass for land there), and stuck at the water's edge he rows across rather than being teleported over it. When a stretch fails, where he couldn't get to is marked impassable for the trip even if he takes the barge, so the route worked out afloat doesn't land him back at the same dead end; and if he has to put out again within a minute of landing, within 32 blocks, that landing place is marked impassable too. A new long-range plan is picked up at the leg he's nearest now (it can take a while to work out): one worked out afloat never sends him back to row its water once he's landed. If his horse gives up following the way short of the end of it (a snag on a corner), he plans that stretch again from where he is; so too the last stretch to the mailbox if it ends with him still too far from the box to walk up to it.
  - The map: after the pickup he walks a few steps (about 3-4 blocks) out from the front of the mailbox, turns the way his route goes, then pulls out a big paper map, holds it open in both hands, bends his head over it and now and then traces the way with a finger, while the long-range plan is worked out (it starts as soon as the pickup ends, so the walk counts). It stays out at least 5 seconds; after about 20 he sets off on the best route found so far and finishes planning on the way. He gets it out again (stopping where he is, on horseback or on foot) whenever the long-range plan has to be redone: his way is blocked, he was teleported free, or he fled. He stops for the map at most once a minute; a re-plan sooner than that happens as he rides.
  - Planning is spread over many ticks with a shared budget, so riders never lag the server; while a new plan is worked out he keeps following the old one.
  - In a world where the long-range plan can't be made (a roof, too big a search), he aims straight for the mailbox and the local plan finds the way; facing water with no dry way on, he takes the barge.
- Vanished riders: the post office notes where every rider out on a delivery is (every couple of seconds). One who disappears without finishing (removed by another mod or a command, say) is brought back after a minute, still carrying the mail: in a puff of smoke where he was last seen, or at the sender's mailbox if that's unknown or nowhere to stand (the void, say), and he whistles up his horse and carries on. If the delivery's world is gone too, he's just taken off the riders who are out. If the original ever turns up, he sees he's been replaced and leaves quietly. Riders, their horses and the barge never go through portals.
- Unstuck: after 30 s without getting 4 blocks nearer (measured as the way he still has to go along his route from where he stands, not as the crow flies, plus half the height still to climb or drop: a detour round a hill that takes him further from the box still counts as getting on, and so does winding up a stair to a box on a tower; the measure starts afresh whenever the route is redone), or 5 s without moving 2 blocks, he first searches for a way through the blocks from where he stands; if there is one he follows it and nobody is moved (once per spot, and a jump doesn't clear that: stuck back by a spot where following failed, he goes straight to the next jump; he's set square in his block first, if the middle of it is standing ground: wedged against a block's edge he'd not get going). If there's none at all, the long-range plan's cells from where he stands to the stretch's goal are struck off the map (a band three cells wide, bar the cell he stands in and the eight round it, or the plan could never leave it) and the route redone round them (the plan took a cliff for a slope, say), which doesn't count as a try against him; up to 24 times a trip. If no route at all can be found from where he is and cells have been struck off, the strikes are more likely to have walled him in than the world, so they're forgiven (bar shores that led nowhere) and the map is tried afresh, once; failing that too, the old route isn't kept to: he heads straight there and the stretches find what they can. While a route is being redone he isn't judged stuck (standing with the map out isn't being stuck: the clocks wait for the new route), nor while he waits for his horse to come to his whistle, the map comes out for it, and once the way ahead has been struck off no stretch follows the old route while the new one is worked out; a route that takes more than a minute to redo is gone by as far as it's got. Failing that he's jumped, with his horse, to the nearest safe spot a way leads on from, trying 2 blocks away first and only then 3, 4, 6, 8, 12 and 16, each searched before he's put there, so a jump is as short as it can be. Stuck again within 4 blocks of where he was last jumped from, the next jump goes further: at least 6 blocks out, then at least 12 (the nearest spot with a way on can lead straight back into the same wedge, as on a village path). Only when none of those will do come the old jumps: a hop ahead if he can, else anywhere round about (even back the way he came); or to the surface if he's underground. No jump ever goes further than 16 blocks, the climb or the drop included (within the chunks that tick round him): with nowhere safe that near, that try finds nowhere to jump to, and it still counts. On the barge he steps ashore if land is at hand, else the long jumps. Six routes redone without his getting any nearer is being stuck too, however busy the map is. Three tries within two minutes, wherever they were and whatever progress he made between, and the delivery fails (tries further apart than that don't add up): jumped about too freely he'd never be stuck, and being stuck now and then is part of the job; a jump or a push-off that puts him further from the box than where he was stuck doesn't reset the count by his coming back to it, he has to get past it. Each jump free is noted in the log with why he was stuck (no nearer in 30 s, or not moved in 5 s), what the route finding was doing, and whether a full search from the spot found a way through the blocks (then the jump wasn't needed); the in-world trials count those, as jumps that weren't needed point at route finding to improve.

## Failure
- Fails when he dies or runs out of unstuck tries.
- Destination mailbox broken or renamed, or inbox full: the Lost Parcel is placed where the mailbox is or was.
- Lost Parcel: a placed block that never despawns. The sender, the recipient, the player who killed the postman, or an operator can open it or break it. Opening it puts its contents in your inventory and removes it. Anyone else who right-clicks it sees who sent it, where it was going and where it came from, but can't take it.
- Lost on the water (killed on the barge, say), it's a floating wreck instead: the soggy, slumped parcel lashed to planks from the barge with one of its oars floating alongside, waterlogged at the surface where he went down, with the skull in his hat or his map as on land. Taking it leaves water behind. Otherwise, with no ground nearby, it floats on any water close by. If there's nothing at all near where he was lost (he fell into the void, say), it goes to the nearest land (or water) within 64 blocks.
- Its look: a battered, torn, grimy parcel with snapped string and a red LOST tag. If the rider was killed, a skull in his cowboy hat lies beside it. If he gave up after getting stuck, a crumpled map lies there instead.
- The sender gets a failure letter in their mailbox. If their mailbox is gone, the failure goes to chat only.

## Notices
- Recipient: chat message when mail arrives (if online), and the flag goes up.
- Sender: chat message when delivered, and a chat message when the postman fails (plus the letter).

## Advancements

A Post Rider tab (tools/gen_advancements.py writes them; one `postrider:post_event` trigger fires them):

- Open for Business (root): get hold of a mailbox. Then Hang Out Your Shingle (name one), Paint the Town (dye one) and Rainbow Route (challenge: all 16 colours).
- First Class (send anything), Signed, Sealed, Delivered (a letter on its own), Pen Pal (10 letters, counted by a Letters Sent statistic).
- You've Got Mail (find a delivery in your box) and Neither Snow nor Rain (mail that crossed water by barge or spent a night on the trail; delivered mail notes both on its tooltip).
- Chris Is Here! (greeted by Chris) and Meet the Crew (challenge: greeted by all 20 riders).
- Home on the Range: come within 12 blocks of a rider's camp.
- Lost and Found (recover a Lost Parcel), Davy Jones' Locker (recover a wreck), Highway Robbery (hidden: open the Lost Parcel of a rider you killed).

## Server config (config/postrider-server.toml)

- `maxRiders` (default 20, 1-20): riders out at once.
- `lookahead` (default 48 blocks, 16-64): how far ahead riders plan; sets how many chunks each keeps loaded.
- `potionsPerDay` (default 2, 0-10).
- `bargeSpeed` (default 8 blocks/s, 2-16).
- `firstCollection` / `lastCollection` (default 6 and 18): the hours riders set out; mail posted outside them waits, and the sender is told when it'll be collected. Riders on the road still camp from dusk to 6am.
- Saving an address and sending mail report back on the mailbox screen itself (a hotbar message would be hidden behind it). The mailbox screen is 248 pixels wide (wider than a chest, the panel art stretched between its ends) so addresses and messages have room; a message that still doesn't fit its lines is cut short with "..." and shown whole when you hover over it.
